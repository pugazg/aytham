# Proof Token Model

## Concept

Represent validated facts as explicit proof/capability values.

Example:

```text
Email
OwnershipProof
MfaProof
NetworkSendCapability
```

## Strengths

- Strong explicit guarantees
- Works well with existing type systems
- Clear action requirements

## Questions

- How are proofs invalidated?
- How is provenance explained?
- How are many independent facts composed?
